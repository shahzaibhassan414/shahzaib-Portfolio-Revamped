What I care about

Stable beats clever

An app that never crashes and loads fast earns more trust than one with a flashy feature that breaks.

Architecture before screens

Planning state, data, and integrations up front is what keeps the tenth feature as easy to add as the first.

No surprises

You always know what shipped, what’s next, and what’s at risk, in plain language rather than jargon.

How I approach an existing codebase

When I take over an app, I don’t start by rewriting it. I read it, run it, and find out where it actually hurts: crash reports, slow screens, flaky builds, state that’s shared in ways nobody intended.

Then I fix what affects users first and improve the structure gradually, so the app keeps shipping while it gets healthier. A full rewrite is sometimes the right call, but it should be a decision backed by evidence, not a reflex.
